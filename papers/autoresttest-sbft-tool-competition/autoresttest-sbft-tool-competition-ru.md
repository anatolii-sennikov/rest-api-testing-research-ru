## Аннотация

Большие пространства входных данных и сложные зависимости между операциями затрудняют тестирование REST API методом «чёрного ящика». AutoRestTest сочетает граф зависимостей семантических свойств (Semantic Property Dependency Graph, SPDG), мультиагентное обучение с подкреплением и большие языковые модели, чтобы целенаправленно исследовать большие пространства входных данных API. В REST League на SBFT 2026 AutoRestTest занял первое место во всех трёх категориях оценки: обнаружение дефектов, общая эффективность и общая результативность. На наборе из 11 API (317 операций, примерно 29 на API) при бюджете времени в час он в среднем выявил 67,09 уникальной ошибки 5xx и успешно выполнил 17,27 операции для каждого API.

**Ключевые слова:** Автоматизированное тестирование REST API, мультиагентное обучение с подкреплением, большие языковые модели

## 1. Введение

REST API лежат в основе современных веб-сервисов, поэтому их автоматизированное тестирование — важное направление исследований. Большинство инструментов в этой области применяют тестирование методом «чёрного ящика»: используют спецификацию OpenAPI (OAS) [[3]](#ref-3), чтобы обращаться к эндпоинтам API без доступа к исходному коду. Для оценки и сравнения ведущих инструментов конкурс REST League [[4]](#ref-4) на SBFT 2026 предоставляет стандартизированный бенчмарк с разнообразными сервисами и проработанными критериями оценки.

Среди шести современных инструментов тестирования REST API методом «чёрного ящика» AutoRestTest занял первое место во всех трёх категориях: обнаружение дефектов, общая эффективность и общая результативность. Этот результат обеспечили три ключевых компонента: граф зависимостей семантических свойств (SPDG), фиксирующий зависимости между операциями; система мультиагентного обучения с подкреплением (MARL) с четырьмя специализированными агентами; модуль генерации значений на основе большой языковой модели (LLM), создающий входные данные с учётом предметной области. AutoRestTest находится в открытом доступе [[6]](#ref-6).

## 2 AutoRestTest

Рабочий процесс AutoRestTest показан на рис. 1. Со времени первой публикации [[2]](#ref-2), [[7]](#ref-7) инструмент доработали по нескольким направлениям. Предварительная обработка с помощью LLM теперь выполняется параллельно для разных операций, что сокращает время подготовки. Агент параметров явно включает все обязательные параметры и применяет стратифицированную выборку к необязательным параметрам, обеспечивая сбалансированное покрытие. Новые мутации граничных значений нацелены на краевые случаи, например пустые строки и экстремальные числовые значения, чтобы вызывать ошибки сервера. Расширенная совместимость с провайдерами LLM позволяет использовать более дешёвые модели и опенсорс-модели, а улучшенный разбор OAS повышает устойчивость при работе с различными спецификациями.

### 2.1 Граф зависимостей семантических свойств

AutoRestTest разбирает OAS и строит граф, в котором каждая операция API представлена вершиной. С помощью компактной модели векторных представлений GloVe [[5]](#ref-5) инструмент измеряет семантическое сходство между параметрами, телами запросов и ответами в парах операций. Если сходство превышает настраиваемый порог, в граф добавляется ребро. Этот взвешенный граф отражает степень зависимости параметров и динамически обновляется во время тестирования по мере обнаружения новых зависимостей.

### 2.2 REST-агенты

AutoRestTest использует четыре специализированных агента. Агент операций выбирает следующий эндпоинт API для исследования. Агент параметров с помощью стратифицированной выборки определяет, какие параметры включить. Агент значений выбирает источники данных и назначает значения из кандидатов, сгенерированных LLM, ранее успешных ответов или значений по умолчанию. Агент зависимостей поддерживает SPDG и отслеживает зависимости между операциями. AutoRestTest также поддерживает агент HTTP-заголовков для простой аутентификации с bearer-токеном, но на конкурсе этот агент был отключён. Каждый агент ведёт Q-таблицу и выбирает действия по ε-жадной стратегии с настраиваемой скоростью обучения и настраиваемым коэффициентом дисконтирования.

### 2.3 Генерация значений на основе LLM

Чтобы сократить расход токенов во время тестирования, AutoRestTest генерирует значения с помощью LLM на параллельном этапе предварительной обработки. Для каждой операции инструмент запрашивает у LLM значения параметров с учётом предметной области и проверяет их на тестируемой системе (System Under Test, SUT). Если проверка не проходит, ответы сервера используются для уточнения запроса. Процесс повторяется до трёх раз для каждой операции. Значения, успешно прошедшие проверку, сохраняются в пространстве действий агента значений для повторного использования при генерации тестов. Если все попытки завершились неудачно, сохраняются значения из последней попытки.

### 2.4 Генерация запросов

После инициализации агентов и предварительной обработки значений AutoRestTest начинает формировать запросы. Каждый агент независимо выбирает действие, после чего полученный запрос отправляется в SUT. Код состояния ответа определяет общий сигнал вознаграждения: ответы 2xx получают приоритет, чтобы строить успешные цепочки запросов, а ответы 5xx вознаграждаются, чтобы стимулировать обнаружение дефектов. Все остальные ответы штрафуются, направляя выбор агентов к продуктивному исследованию пространства состояний API; Q-таблицы обновляются соответствующим образом.

Чтобы выявлять краевые случаи и внутренние ошибки сервера, AutoRestTest применяет мутации к уточнённым телам запросов. Мутации включают изменение типов и имён параметров, типов содержимого и подстановку граничных значений.

## 3 Оценка в REST League

Мы представили AutoRestTest на конкурсе REST League [[4]](#ref-4) в рамках SBFT 2026. Для оценки использовались 11 реальных REST API с 317 операциями — примерно 29 операциями на API. Организаторы запускали каждый инструмент по 10 раз для каждого API, отводя на один запуск один час, и усредняли результаты, чтобы учесть недетерминированность.

**Конфигурация.** Мы настроили AutoRestTest с порогом семантического сходства 0,7, ε-жадной стратегией исследования со снижением ε с 1 до 0,2, скоростью обучения α = 0,1, коэффициентом дисконтирования γ = 0,9 и вероятностью мутации 0,2. Для генерации значений с помощью LLM мы установили температуру 1, чтобы разнообразить результаты, и использовали недорогую модель Gemini 2.5 Flash Lite [[1]](#ref-1), чтобы сократить расходы на прогоны при отсутствии кэширования.

**Критерии оценки.** REST League определяет три категории, нормализованные по Z-оценке и называемые в конкурсе задачами (*challenges*) [[4]](#ref-4): обнаружение дефектов — уникальные ошибки 5xx; общая эффективность — AUC во времени для дефектов, операций и покрытия; общая результативность — совокупность итоговых значений обнаружения дефектов, покрытия операций и покрытия ветвей.

**Результаты.** AutoRestTest получил наивысшую оценку во всех трёх категориях, превзойдя CATS, EvoMaster, RESTest, RestTestGen и Schemathesis. В среднем он обнаружил в 2,7 раза больше дефектов (67,09), чем инструмент, занявший второе место в этой категории (24,65). AUC обнаружения дефектов у AutoRestTest оказался в 2,3 раза выше (151 490 против 66 761 у ближайшего конкурента). Это показывает, что архитектура MARL и стратегия уменьшения ε позволяют быстро создавать результативные тесты, что особенно важно при жёстком ограничении времени. Кроме того, AutoRestTest обеспечил наибольшее среднее покрытие операций (17,27), продемонстрировав широкий охват без потери глубины. Полные результаты приведены в отчёте о конкурсе [[4]](#ref-4).

Во всех прогонах AutoRestTest израсходовал примерно 9,6 млн входных и 2,2 млн выходных токенов. Общие затраты составили около 1,83 долл. США, или примерно 0,02 долл. США за один прогон для одного сервиса.

Несмотря на высокие результаты в целом, при работе с API flight-search произошёл сбой: парсер ответов неявно предполагал, что все ответы используют кодировку UTF-8. В будущих версиях парсер будет корректнее обрабатывать различные кодировки ответов.

## 4 Заключение

Мы представили AutoRestTest и его результаты на конкурсе REST League SBFT 2026 [[4]](#ref-4). Инструмент занял первое место по обнаружению дефектов, общей эффективности и общей результативности благодаря исследованию зависимостей с помощью SPDG, адаптивной генерации тестов на основе MARL и генерации значений с помощью LLM. AutoRestTest обнаружил в 2,7 раза больше дефектов, чем инструмент, занявший второе место, при затратах около 0,02 долл. США за один прогон для одного сервиса. Дальнейшая работа будет направлена на более надёжный разбор ответов и более информативные сигналы вознаграждения, чтобы инструмент устойчивее работал с различными API. AutoRestTest распространяется как опенсорс и находится в открытом доступе [[6]](#ref-6).
